# Баня «Весна»

[Открыть сайт бани «Весна»](https://shushakovd83-jpg.github.io/bana/)

Сайт бани в Чайковском с публичной формой, закрытым журналом владельца по адресу /admin и выгрузкой Excel. Гостевой сайт публикуется через GitHub Pages из корня ветки main. Интерфейс администратора лежит в dist, серверный код — в src. Страница формы требует работающего серверного API.

## Сборка
Установите Node.js 22 или новее. Выполните npm ci и npm run build. Готовый модуль Worker находится в dist/server/index.js.

## Размещение
Проект рассчитан на ChatGPT Sites с серверной авторизацией платформы. Привяжите закрытое хранилище R2 под именем BUCKET и задайте JOURNAL_OWNER_EMAIL как секрет окружения. Платформа должна удостоверять пользователя и устанавливать заголовки oai-authenticated-user-id и oai-authenticated-user-email сама. При самостоятельном размещении требуется заменить проверку личности или использовать доверенный шлюз, который удаляет переданные клиентом заголовки. GitHub Pages обслуживает только статические файлы.

## Журнал и Excel

Форма на GitHub Pages обращается к серверу сайта. После каждой заявки и каждого изменения брони сервер сохраняет настоящий файл Excel в закрытом хранилище. Успешный ответ формы означает, что файл записан. Повторная отправка той же заявки сохраняет одну строку.

Владелец открывает [журнал](https://vesna-banya-chaikovsky.almondmarmalade4.chatgpt.site/admin) на компьютере или телефоне и нажимает «Скачать Excel». Сервер хранит актуальную таблицу, а скачанный файл содержит данные на момент загрузки.

## Уведомления о заявках

1. В сообществе nagore59 включите сообщения. Из профиля e.shushakov напишите «Начать» в [чат сообщества](https://vk.me/nagore59).
2. В «Управление → Работа с API → Ключи доступа» создайте ключ сообщества с правом на сообщения.
3. В разделе «Уведомления ВКонтакте» закрытого журнала введите ключ и нажмите «Отправить проверку и подключить». Сервер сохраняет ключ после успешного проверочного сообщения администратору.

Одна заявка создаёт одну запись в очереди. После записи Excel сервер сразу пробует отправить уведомление. Ожидающие сообщения обрабатываются при подключении ВК, при следующих заявках и по кнопке «Повторить отправку». При повторе VK получает тот же random_id. В очереди остаются сообщения, которые VK ещё не принял.

Для шифрования ключа на сервере нужен постоянный секрет VK_SETTINGS_KEY (32 случайных байта в формате Base64). Его задают через Sites и сохраняют между выпусками. Уже развёрнутые конфигурации с VK_TOKEN и VK_ADMIN_PEER продолжают работать.

## Напоминания о визите

Для привязки гостя к его заявке настройте VK_GROUP_ID, VK_CALLBACK_SECRET и VK_CONFIRMATION и подключите Callback API сообщества к /vk/callback (версия 5.199, событие message_new). Гость открывает персональную ссылку после отправки формы и пишет сообществу. Обработчик очереди готовит напоминания за сутки до подтверждённого визита администратору и гостю, привязавшему диалог.

Для автономного обхода очереди доступен инструмент владельца process_booking_notifications через подключение этого сайта в Sites. Он обновляет Excel, вызывает отправку и возвращает только состояние файла и счётчики. На платформе с расписаниями Worker можно также вызвать обработчик scheduled. Рабочий журнал, телефоны гостей и ключи хранятся в закрытом хранилище.
